Rules small enough
to sign off.

A rule is a Weft-8 program with a contract: the caller puts inputs in the ports, the rule writes one byte — pass, flag or stop. Twenty lines, no model, no inference, and a machine that cannot reach a file, a network or a page. If a rule matters enough to argue about, it matters enough to be readable.

What a kit buys you

Three properties that a rules engine in a general-purpose language struggles to promise, and that this one can state plainly.

Readable

A rule is twenty lines you can read aloud. No callbacks, no hidden state, no library deciding what "and" means.

Bounded

The machine has a step limit and 27 opcodes, none of which touch a file, a network or a page. A runaway rule stops and says so.

Provable

Every rule ships its cases, and the test suite runs them on the real machine — including the case where the comparison is flipped, to prove the test bites.

The limits, stated: this machine compares signed bytes, so an input above 127 reads as negative — every rule here says so where it matters. And the four rules shipped are examples of the pattern, not clinical guidance.

The contract

Inputs at 0xD0–0xD3, verdict at 0xD7. That is the whole interface — the same in the browser, in a test, and in any app that adopts the kit.

  • Adopt it in two files: weft8.js and rules.js, copied in. No build step, no dependency, no network.
  • Built on the Loom. The machine is weft8.js from app-jacquard, byte for byte the same engine.
  • Diffable. A rule is text: it goes in a pull request, it gets reviewed, and the reviewer can see exactly what changed in the decision.
